# أدلة الجولة الأولى — الكاشير والطلبات

تاريخ الجولة: 2026-10-02. مراجعة محدودة لمسار الحفظ والمزامنة، وليست اختبار E2E أو إكمال مرحلة Baseline في خطة MVP.

- [نسخ المستودعات وحالة الملفات](baseline.txt).
- [بصمات ملفات POS وقت أخذ النسخة](pos-file-sha256.json).
- [نتيجة الاختبارات](focused-tests.txt): 3 ملفات، 60 اختبارًا ناجحًا، كود خروج 0.

نُسخت ملفات المشروع إلى مجلد مؤقت مذكور في baseline.txt، بما فيها ملفات tsconfig الخاصة بـElectron. استُخدمت الاعتماديات المثبتة بالفعل عن طريق رابط node_modules؛ لم يُنفذ npm ci. التعديل الوحيد على إعداد الاختبار في النسخة المؤقتة هو نقل cacheDir إلى مجلدها. لم يُعدّل كود POS الأصلي. الأمر من مجلد النسخة:

```sh
node node_modules/vitest/vitest.mjs run --configLoader runner src/pos/db/orderOutboxRepo.test.ts src/pos/db/syncScheduler.test.ts src/pos/usePos.orderSubmission.test.ts
```

الاختبارات تستخدم SQLite في الذاكرة ومحاكاة API/التخزين في اختبار الواجهة؛ لا تختبر OPFS على جهاز فعلي أو PostgreSQL أو الطابعة. بيئة التشغيل Node 20.20.2 وVitest 4.1.10. لم تُشغّل اختبارات Backend في هذه الجولة.

المحاولة السابقة قبل توقف المستخدم موجودة في مجلد pos-01 ببصمات فقط؛ توقفت محاولة الاختبار السابقة قبل تشغيل الاختبارات بسبب عدم نسخ tsconfig.electron.json إلى البيئة المؤقتة. ليست فشلًا مثبتًا في المنتج، ولا تدخل في نتيجة هذه الجولة.
