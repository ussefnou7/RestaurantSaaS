# أدلة تجربة Electron 22

التاريخ: 2026-10-02. النظام المنفذ: **Linux x64**. المحرك الفعلي: **Electron 22.3.27 / Chromium 108 / Node 16.17.1**. هذه ليست نتائج Windows.

## النتائج

| التجربة | النتيجة | الدليل |
|---|---|---|
| SQLite الحالي + OPFS في Worker وتطبيق schema الفعلي | نجحت؛ user_version = 34 | [كتابة الطلب](write-result.json) |
| إعادة تشغيل العملية بنفس التخزين | نجحت؛ المفتاح والنص العربي والمبلغ والعدد، ثم تنظيف المتزامن | [التحقق بعد إعادة التشغيل](verify-result.json) |
| بناء الواجهة بهدف chrome108 | نجح | [سجل البناء](renderer-build.log) |
| تحميل شاشة إعداد الجهاز ورسم إيصال عربي | نجح في غلاف تجربة مستقل | [نتيجة الواجهة](ui-result.json)، [الشاشة](login.png)، [الإيصال](receipt.png) |
| تحويل الغلاف الحقيقي إلى CommonJS وبروتوكول قديم في نسخة مؤقتة | TypeScript والبناء نجحا | [سجل TypeScript](shell-build.log)، [سجل Vite](shell-renderer-build.log)، [الفرق التجريبي](experimental-shell.diff) |
| تشغيل الغلاف المعدل وتمرير API والتعامل مع انقطاع الاتصال | نجح أمام خادم loopback تجريبي | [نتيجة الغلاف](shell-result.json) |
| مسار الإيصال الفعلي: renderReceiptBitmap ثم buildReceiptJob | نجح؛ 28981 بايت | [بيانات ESC/POS التجريبية](synthetic-receipt.escpos) |

تمت مشاهدة صورة الإيصال؛ النص العربي والمبالغ ظاهرة. هذا لا يقيس جودة الورق أو تعريف الطابعة أو كامل تدفق إيصال الدفع الحقيقي. مصدر الإيصال بيانات صناعية وليست عملية بيع.

غلاف التجربة يستخدم userData منفصلًا. لا اتصالات بخادم المشروع ولا بيانات عملاء ولا Windows spooler. فحص API يثبت POST والنص العربي والمبلغ في الحمولة وAuthorization تجريبيًا، وبقاء HTTP 503 كرفض HTTP، وتحول قطع الاتصال إلى رفض fetch. لا يثبت كل صيغ HTTP أو الملفات الكبيرة أو سياسة التحويلات أو TLS.

## إعادة التجربة

[أدوات التجربة وتعليماتها](../../../../scripts/compatibility/electron22/README.md).

نُزّل electron-v22.3.27-linux-x64.zip من إصدار Electron الرسمي، وتطابقت بصمته مع SHASUMS256.txt المنشور:

`631d8eb08098c48ce2b29421e74c69ac0312b1e42f445d8a805414ba1242bf3a`

المجلد المؤقت المستخدم: `/tmp/pos-win7-probe/`. الملفات المؤقتة ليست مخرجات توزيع. [بصمات مصادر التخزين](storage-source-sha256.json)، [بصمات مصادر نسخة الغلاف المعدلة](staged-source-sha256.json).

المحاولة الأولى لتشغيل Electron داخل عزل Codex فشلت عند تهيئة sandbox؛ التجارب الناجحة شُغّلت خارج عزل Codex دون إضافة --no-sandbox. كذلك أُصلح قارئ JSONC في أداة staging ونوع stream في المحول التجريبي قبل إعادة بناء ناجحة. هذه مشكلات إعداد تجربة وليست نتائج اختبار Windows.

## حدود النتيجة

- لم يُغيّر مستودع POS الأصلي أو package-lock أو إصدار Electron المثبت فيه.
- لا حزم Windows جاهزة ولا اختبار Windows 7/10 أو 32 بت بعد.
- لا اختبار انقطاع كهرباء أو ضغط أو ترقية تخزين قديم.
- لم يُختبر تحميل Koffi على Windows أو إرسال البايتات للطابعة.
- adapter البروتوكول هنا تجريبي؛ مراجعته وتغطيته قبل اعتماده للإنتاج متبقيتان.
