## طريقة العمل معًا

1. نثبت استخدام العميل في التشغيل الأول، ونختار موديولًا واحدًا للمراجعة. تم تحديد الاستخدام الأساسي في صفحة النطاق؛ البداية بالكاشير والطلبات ثم الشيفتات.
2. نجمع قراراته ووثائقه ونشرح قواعده بالعربي بأمثلة عملية، مع الاحتفاظ بمعرّفات القرارات.
3. نفحص مسار التنفيذ في الخلفية والواجهة عند الحاجة، ونسجل الملفات ونسخة الكود التي فُحصت.
4. نراجع الاختبارات: ماذا تغطي فعلًا؟ ما نتيجة آخر تشغيل موثّق؟ وما السيناريوهات التي لم تُختبر؟
5. نعرض الأسئلة المفتوحة على صاحب المنتج بمثال ونتيجته المتوقعة. الإجابة تُسجل بتاريخها؛ القرار الجديد أو التعديل الصريح لقرار قائم يُوثق في سجل القرارات مع الحفاظ على تاريخه.
6. نجهز حالات اختبار يدوي بنتائج متوقعة. تُسجل النتيجة الفعلية والدليل ونسخة التطبيق عند التنفيذ.
7. نحدّث الفصل وروابط الملاحظات، ثم نحفظ نسخة مؤرخة عند اكتمال جولة المراجعة.

وجود كود لا يعني اكتمال الميزة. وجود اختبار لا يعني أنه نجح، ونجاح اختبار منفرد لا يثبت سلامة المسار كاملًا أو التزامن بين طلبين.

## كيف نعرض حالة كل نقطة؟

نفصل بين **حالة التنفيذ** و**قوة الدليل**:

| البعد | القيم المستخدمة |
|---|---|
| التنفيذ | غير مفحوص / منفذ / منفذ جزئيًا / غير منفذ / خارج نطاق التشغيل الأول |
| الدليل | منقول من وثيقة فقط / مفحوص في الكود / اختبار آلي ناجح موثق / اختبار يدوي ناجح موثق / فشل موثق |
| نوع المتابعة | سؤال أعمال / اشتباه يحتاج فحصًا / فجوة اختبار / مشكلة مؤكدة مرتبطة بالسجل / ميزة مقترحة مرتبطة بخارطة العمل |

كل دليل يحمل تاريخًا ونسخة كود ونطاقًا واضحًا. «غير مفحوص» لا تعني «غير منفذ». ولا نحكم بأن الاختبارات غير كافية من عدد الملفات وحده؛ نربط التغطية بسيناريوهات العمل والمخاطر.

المشاكل المؤكدة ترتبط بمعرّفها `L###` في السجل المركزي، وتظل صلاحيات تعديل شدتها وأدلتها وإغلاقها وفق الخطة الحالية. اقتراح ميزة لا يُعامل تلقائيًا كعيب أو كقرار بتنفيذها.

## النسخ والتعديل

- الملفات في هذا المجلد هي النسخة الحية التي نعدلها تدريجيًا.
- عند اكتمال مراجعة موديول أو اعتماد جولة قبل الإطلاق، ننسخ الدليل إلى `versions/YYYY-MM-DD-vX.Y/` دون تضمين مجلد `versions` نفسه. تُنسخ الفصول والقوالب والمرفقات المحلية اللازمة وتُراجع الروابط.
- النسخة المؤرخة لا تُعدّل؛ أي تصحيح يظهر في نسخة لاحقة وسجل التعديلات.
- كل نسخة تحفظ حالة المعرفة وقتها، ولا تحفظ نسخة من البرنامج أو قاعدة البيانات. روابط الوثائق الخارجية تشير إلى ملفات حية؛ لذلك يسجل كل فصل مراجع نسخ الكود والأدلة عند التحقق.
- تُحفظ الملفات في Git مع تغييرات التوثيق عند الالتزام بها. إنشاء هذه النسخة لا يعني إنشاء commit أو tag تلقائيًا.
