## 2. §0 — the shared line-schema regression gate

The concern was that `useDocumentLines.ts:232` (`if (field.visible && !field.visible(ctx)) continue`)
could silently disable validation on screens other than Purchase Invoice.

**It cannot.** `visible` is a *new* optional property (`lineSchema.ts:41`) and it is set on exactly
one field in the whole codebase — the expiry-date field at `purchaseInvoiceLineSchema.ts:113`.
On Purchase Return, Waste and Asset schemas `field.visible` is `undefined` for every field, so the
guard short-circuits and validation runs exactly as before. That is the static proof; below is the
exercised result.

Exercised in the browser against the running dev backend (tenant `f7am`, port 2020, client on 5180).
Fixtures created: waste document 61 (`WS/26/000001`), purchase return 17 (`PR/26/000001`),
asset 26 (`Recon Test Chairs`). All are drafts in the dev database and can be deleted.

| **Waste** | Form | ✅ Tomato 2 added (Item 1 of 2) | ✅ 7.5 → 4.25 | ✅ `Quantity must be greater than zero.` | ✅ same four |

**Assets edit is not applicable, by design.** `assetLineSchema.ts:108-130` defines exactly three
row actions — `maintenance`, `dispose`, `delete`. There is no `edit` action and no `onUpdateLine`.
The browser confirms it: the only row buttons are Maintenance, Dispose, Delete. This predates the
shared-schema change and is not a regression. The prior remediation report said the same thing and
it holds.

No field that should be visible was missing; no field that should be hidden appeared. The expiry

## 7. Claims that do not hold

**FALSE — "Arabic-Indic digits on the batch table's existing date and quantity columns."**
The code does the opposite, deliberately. `src/utils/format.ts:11` returns `'ar-EG-u-nu-latn'`
for Arabic; the `-nu-latn` Unicode extension **forces Latin digits**. `WarehouseStockBatchSubRow.tsx`
routes its date and quantity columns through `formatDate` and `formatNumber` (`:153`, `:167-168`),
both of which use that locale. Arabic renders Latin digits by design. No Arabic-Indic conversion
exists anywhere in the file.

**FALSE — "the dead key `inventory.purchase.lines.notes` was deleted."**
It is still present at `src/i18n/locales/en/inventory.ts:584`, in both HEAD and the working tree.
The Arabic file never had it. The locale deletions in the diff removed the *transfer* keys
(`inventory.transfers.*`), not this one.

`أدخل تاريخ انتهاء الصلاحية للمادة {{materialName}} قبل ترحيل فاتورة الشراء.` Whether that is
shorter than some earlier draft cannot be checked from the repository.
